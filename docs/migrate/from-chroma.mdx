Here is how the migration works:

1. A script exports every collection to JSONL and writes a TopK import spec for it, with the vector dimension, the distance metric and a typed field for each metadata key.
2. [`topk import`](/cli#import) loads each spec into a new collection.
3. You switch your queries to the TopK SDK.
4. A second script compares record counts and sample query results between Chroma and TopK.

Your embeddings are copied as they are. Nothing is re-embedded.

## How Chroma concepts map to TopK

| Chroma | TopK |
| - | - |
| Collection | Collection |
| Record id | `_id` |
| Embedding | [`f32_vector()`](/sdk/topk-py/schema#f32_vector) field with a [`vector_index()`](/sdk/topk-py/schema#vector_index) |
| Metadata | Typed fields, usable in filters |
| Document | Text field with a keyword or semantic index |
| `space`: `l2` / `cosine` / `ip` | `metric`: `euclidean` / `cosine` / `dot_product` |
| `query(n_results=10)` | [`.limit(10)`](/sdk/topk-py/query#limit) |
| `where` | [`.filter()`](/collections/query#filtering) |
| `where_document={"$contains": ...}` | [`field("document").contains(...)`](/collections/query#contains) |
| One collection per tenant | [Partitions](/concepts#multi-tenancy) in one collection |

## Step 1: Export every collection

Save this as `chroma_to_topk.py` and run it with your Chroma credentials in the environment. It walks every non-empty collection in the database and writes `<collection>.jsonl` and `<collection>.toml` to the current directory.

```python chroma_to_topk.py
import json
import os

import chromadb

# Chroma space -> TopK vector metric
METRICS = {"l2": "euclidean", "cosine": "cosine", "ip": "dot_product"}
TYPES = {bool: "bool", int: "int", float: "float", str: "text"}

chroma = chromadb.CloudClient(
    tenant=os.environ["CHROMA_TENANT"],
    database=os.environ["CHROMA_DATABASE"],
    api_key=os.environ["CHROMA_API_KEY"],
)

for col in chroma.list_collections():
    if col.count() == 0:
        continue
    config = col.configuration
    space = (config.get("spann") or config.get("hnsw") or {}).get("space", "l2")
    fields, dim = {}, None

    with open(f"{col.name}.jsonl", "w") as out:
        for offset in range(0, col.count(), 1000):
            page = col.get(
                limit=1000,
                offset=offset,
                include=["documents", "metadatas", "embeddings"],
            )
            for id, doc, meta, emb in zip(
                page["ids"], page["documents"],
                page["metadatas"], page["embeddings"],
            ):
                dim = len(emb)
                for key, value in (meta or {}).items():
                    kind = TYPES.get(type(value))
                    if kind is None or key in ("id", "document", "embedding"):
                        continue
                    seen = fields.setdefault(key, kind)
                    if seen == "int" and kind == "float":
                        fields[key] = "float"
                out.write(json.dumps({
                    **(meta or {}),
                    "id": id,
                    "document": doc,
                    "embedding": [float(x) for x in emb],
                }) + "\n")

    with open(f"{col.name}.toml", "w") as spec:
        spec.write(
            f'["{col.name}"]\nfrom = "{col.name}.jsonl"\nid = "id"\n\n'
            f'["{col.name}".fields]\n'
            'document = { type = "text", index = "keyword" }\n'
        )
        for key, kind in fields.items():
            spec.write(f'{json.dumps(key)} = {{ type = "{kind}" }}\n')
        spec.write(
            f'\n["{col.name}".fields.embedding]\n'
            f'type = "f32_vector"\ndim = {dim}\n'
            f'index = {{ vector = {{ metric = "{METRICS[space]}" }} }}\n'
        )

    print(f"{col.name}: {col.count()} records, {dim} dims, {space}")
```

```bash
export CHROMA_TENANT=... CHROMA_DATABASE=... CHROMA_API_KEY=...
python chroma_to_topk.py
```

```text Output
docs: 120000 records, 1536 dims, cosine
tickets: 48210 records, 768 dims, ip
```

<Note>
  On self-hosted Chroma, replace `chromadb.CloudClient(...)` with `chromadb.HttpClient(host=..., port=...)`. Everything else stays the same.
</Note>

<Note>
  The script reads each collection's distance function from its configuration, so a collection created with `cosine` or `ip` keeps that metric in TopK. Collections without an explicit `space` use Chroma's default, `l2`.
</Note>

## Step 2: Review the import spec

Each generated spec is a plain [import spec](/cli#spec). For a collection called `docs`, it looks like this:

```toml docs.toml
["docs"]
from = "docs.jsonl"
id = "id"

["docs".fields]
document = { type = "text", index = "keyword" }
"source" = { type = "text" }
"year" = { type = "int" }

["docs".fields.embedding]
type = "f32_vector"
dim = 1536
index = { vector = { metric = "cosine" } }
```

Two edits are worth considering before you import:

- **Let TopK embed the text too.** Change the document's index from `"keyword"` to `"semantic"` and TopK generates [multi-vector embeddings](/guides/semantic-search) for it, alongside your existing vectors. You can then query with [`fn.semantic_similarity()`](/sdk/topk-py/query#semantic_similarity) and skip the query embedding call.
- **Drop fields you don't query.** The spec is a whitelist: only the fields it declares are imported.

## Step 3: Import into TopK

Log in once, then import every spec:

```bash
topk login
for spec in *.toml; do
  topk import -f "$spec" --region aws-us-east-1-elastica --yes
done
```

Pick the region closest to your application from [Regions](/regions). Each spec creates its collection and loads it; documents are searchable as soon as they are written.

<Tip>
  - Add `--dry-run` to print the plan and a sample of documents without writing anything.
  - If a run stops, re-run it with `--resume <run-id>`, using the run id printed when it started. Upserts are idempotent, so re-running from scratch is safe too.
  - To merge per-tenant collections into one collection, add a tenant column to each record and import with `--partition <column>`. Each tenant gets its own isolated partition.
</Tip>

## Step 4: Update your queries

Chroma's `query()` becomes a TopK query that selects a score, sorts by it and limits the results:

<CodeGroup>

```python Chroma
results = collection.query(
    query_embeddings=[query_vector],
    n_results=10,
    where={"source": "handbook"},
)
```

```python TopK
from topk_sdk import Client
from topk_sdk.query import select, field, fn

client = Client(api_key=TOPK_API_KEY, region="aws-us-east-1-elastica")

results = client.collection("docs").query(
    select(
        "document",
        score=fn.vector_distance("embedding", query_vector),
    )
    .filter(field("source") == "handbook")
    .sort(field("score"), asc=False)
    .limit(10)
)
```

</CodeGroup>

<Warning>
  Sort direction depends on the metric. For `cosine` and `dot_product`, a higher score is closer, so sort with `asc=False`. For `euclidean`, a lower score is closer, so sort with `asc=True`.
</Warning>

### Filter operators

| Chroma `where` | TopK `.filter()` |
| - | - |
| `{"year": 2024}` or `{"year": {"$eq": 2024}}` | `field("year") == 2024` |
| `{"year": {"$ne": 2024}}` | `field("year") != 2024` |
| `{"year": {"$gt": 2020}}` | `field("year") > 2020` (also `>=`, `<`, `<=`) |
| `{"source": {"$in": ["wiki", "handbook"]}}` | `field("source").in_(["wiki", "handbook"])` |
| `{"source": {"$nin": ["wiki"]}}` | `not_(field("source").in_(["wiki"]))` |
| `{"$and": [a, b]}` | `(a) & (b)` |
| `{"$or": [a, b]}` | `(a) \| (b)` |
| `where_document={"$contains": "refund"}` | `field("document").contains("refund")` |

Wrap each comparison in parentheses when you combine them with `&` or `|`, because Python binds `&` and `|` more tightly than `==`, `>` and the other comparisons. `not_` is imported from `topk_sdk.query`. Both `$contains` and `contains()` are case-sensitive substring matches.

## Step 5: Check that results match

Run this while Chroma still serves reads. It compares record counts, then runs 20 of your own vectors as queries against both systems and prints how many of the top 10 results they share.

```python verify.py
import os

import chromadb
from topk_sdk import Client
from topk_sdk.query import select, field, fn

chroma = chromadb.CloudClient(
    tenant=os.environ["CHROMA_TENANT"],
    database=os.environ["CHROMA_DATABASE"],
    api_key=os.environ["CHROMA_API_KEY"],
)
topk = Client(api_key=os.environ["TOPK_API_KEY"], region="aws-us-east-1-elastica")

src = chroma.get_collection("docs")
dst = topk.collection("docs")
print("records:", src.count(), dst.count())

for q in src.get(limit=20, include=["embeddings"])["embeddings"]:
    q = [float(x) for x in q]
    want = src.query(query_embeddings=[q], n_results=10)["ids"][0]
    got = dst.query(
        select(score=fn.vector_distance("embedding", q))
        .sort(field("score"), asc=False)  # asc=True for euclidean
        .limit(10)
    )
    print(len(set(want) & {d["_id"] for d in got}), "/ 10 shared")
```

Both systems use approximate nearest neighbor indexes, so expect close to 10 shared results per query rather than identical lists every time. A count mismatch usually means the import stopped early: re-run it with `--resume`.

## Things to know

- **Unsupported metadata values are skipped.** The spec only declares string, integer, float and boolean metadata. Other values, such as lists, stay in the JSONL but aren't imported unless you add them to the spec with a [list type](/cli#spec).
- **Reserved names.** Metadata keys called `id`, `document` or `embedding` are overwritten by the record's own values. Rename them in the script if you use them.
- **Records without a document** import without one; the `document` field is optional.
- **Squared L2.** Chroma's `l2` is squared Euclidean distance. TopK's `euclidean` ranks results in the same order, but the scores differ.
